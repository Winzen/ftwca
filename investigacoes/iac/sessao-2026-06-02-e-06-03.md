### 7. Issue #1571 — Chamada HTTP no nível do módulo quebrava o deploy

**Link:** https://github.com/basedosdados/pipelines/issues/1571

**Problema:** o deploy de produção quebrou com `ConnectTimeout` para `arquivos.receitafederal.gov.br` durante a etapa **Perform code tree analysis** no CI.

**Causa raiz:** `br_rf_cafir/tasks.py` linha 26 chamava `get_last_update_date()` no nível do módulo, fora de qualquer função ou task:

```python
# Errado — executa no import
last_update_date = get_last_update_date(url=br_rf_cafir_constants.URL.value)
```

O script `code_tree_analysis.py` importa todos os módulos de flows para verificar conflitos de nomes — disparando a chamada HTTP no runner do GitHub Actions, que não tem acesso ao host da Receita Federal.

**Solução:** mover `get_last_update_date()` para dentro das tasks que a utilizam (`task_decide_files_to_download` e `task_download_files`), nunca no nível do módulo.

> **Padrão a seguir:** nunca fazer chamadas de rede, I/O ou operações com efeitos colaterais fora de funções/tasks. O import de um módulo deve ser sempre seguro e sem efeitos.
